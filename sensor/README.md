# Правила Suricata

| SID | Что означает алерт | Что сверить при разборе |
| --- | --- | --- |
| 1000001 | Запрос лабораторного маркера `/soc-lab-canary` | Время испытания, источник и адрес тестового сервиса |
| 1000002–1000004, 1000008, 1000015 | В открытом HTTP видны заголовок авторизации, сессионная cookie, токен в URL или поле API-ключа | Где завершается TLS, какие клиенты ходят открытым HTTP и какой компонент пишет журналы запросов |
| 1000005–1000007, 1000014 | TRACE, CONNECT, бинарная загрузка PUT или WebDAV PROPFIND | Разрешённые методы и назначение сервиса. Для прокси CONNECT, а для WebDAV PROPFIND могут быть штатными |
| 1000009–1000011 | Обращение к пути администратора, SQL-бэкапу или диагностическому маршруту | Ответ HTTP, адрес назначения и журнал приложения. 404 и 200 дают разные основания для расследования |
| 1000012–1000013 | Старый клиент инвентаризации или прокси-заголовок на прямом участке | Версию клиента и точку захвата. На участке после доверенного прокси X-Forwarded-For может быть штатным |
| 1000016–1000019 | Имя WPAD, запрос `.local` к обычному DNS, имя из списка наблюдения или длинная шестнадцатеричная DNS-метка | Имя, резолвер, частоту запросов и назначение источника. Длинная метка сама по себе требует контекста |
| 1000020–1000022 | SYN на Telnet/FTP-порт или TFTP read opcode на UDP 69 | Предполагаемый протокол, ответ назначения и перечень разрешённых сервисов |

`./lab test` обрабатывает синтетический Ethernet PCAP с 22 положительными и 11 контрольными сценариями. Проверка сопоставляет каждый алерт с ожидаемым идентификатором правила и потоком. Для контрольных запросов она проверяет присутствие потока в EVE и отсутствие неожиданных алертов. Названия и входные данные сценариев находятся в [fixtures.py](fixtures.py).

Правила описывают политику учебной сети. Перед адаптацией к другому сегменту определите разрешённые сервисы и уточните адреса в заголовках правил. Данные в PCAP синтетические. Время в нём фиксировано для воспроизводимости.
